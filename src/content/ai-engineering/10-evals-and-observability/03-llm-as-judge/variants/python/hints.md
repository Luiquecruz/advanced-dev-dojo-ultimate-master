Build the request from the rubric: turn each criterion into a line `- name: description`, mention `rubric["scale"]["min"]` and `rubric["scale"]["max"]`, and describe the JSON shape. Keep the answer out of the system message; wrap it in tags inside the user message. `parse_judgment` is `parse_model_json(text)` plus a loop over `rubric["criteria"]` that returns `None` at the first missing, non-integer (`isinstance(score, int) and not isinstance(score, bool)`) or out-of-range score.
---
`judge_answer` is a bounded loop: `for attempt in range(1, max_attempts + 1):`, return as soon as `parse_judgment` gives scores, and after the loop return `{"valid": False, "attempts": max_attempts, "reason": ...}`. For kappa, count each label's share in both lists (a dict per list), sum `share_first × share_second` over the labels of `first`, and apply the formula, with the special case `expected == 1`.
---
For `compare_pairwise`, read `"winner"` from each reply with `parse_model_json` (check that the value is a dict first). In the first call `"first"` means A; in the swapped call `"first"` means B. Anything other than `"first"`, `"second"` or `"tie"` is a `None` vote. Only equal, non-`None` votes produce a winner; every other combination is an inconsistent tie.
