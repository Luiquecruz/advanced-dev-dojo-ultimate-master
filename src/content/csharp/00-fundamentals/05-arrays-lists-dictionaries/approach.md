1. Pick the container each job needs. A count per word is a lookup by key, so `Words.Count` fills a `Dictionary<string, int>`. The restock answer is a row of numbers whose length you do not know in advance, so it is a `List<int>`. The cart is already an array of tuples, and the prices are a dictionary you only read.
2. `Stock.Restock` needs the position of each level, so it uses a `for` loop from `0` while `i < levels.Length`. With `<=` the last pass reads one past the end and throws `IndexOutOfRangeException`. It adds `i` when `levels[i] < minimum`; `<=` would also restock a level that is exactly at the minimum.
3. `Cart.Total` deconstructs each line into `sku` and `quantity` and asks the dictionary with `TryGetValue`. The indexer `prices[sku]` would throw `KeyNotFoundException` on the first SKU without a price; `TryGetValue` returns `false` instead, and the line is skipped. The total is a `decimal`, because it is money.
4. `Words.Count` builds words character by character. A letter is lowercased and appended to a `StringBuilder`; any other character ends the current word. Ending a word means: skip it if it is empty (two separators in a row), otherwise read its old count with `TryGetValue` (which leaves `0` for a new word), store one more, and clear the builder.
5. The loop ends without a separator after the last word, so the "end a word" step runs once more after the loop. Putting it in a small helper method avoids writing it twice (`private` means only this class can call it; 00/06 explains it).
