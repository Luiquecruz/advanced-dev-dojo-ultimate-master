1. Read each requirement as a guard: what input must the method refuse, and how? `Divide` refuses a divisor of `0` with a return value, `Parse` refuses bad text and out-of-range numbers by throwing.
2. `Safe.Divide` checks `b == 0` first and returns `(false, 0)`, so the division, which would throw `DivideByZeroException`, never runs with a zero divisor. Otherwise it returns `(true, a / b)`; dividing two `int`s drops the remainder, as in 00/01.
3. `Ages.Parse` uses `int.TryParse` rather than `int.Parse`. Bad text is expected input here, and `int.Parse` would answer it with a `FormatException`, the wrong type. When `TryParse` returns `false`, the method throws `ArgumentException` with the parameter name, `nameof(text)`.
4. The range check comes second, because it needs the parsed number. A value below `0` or above `150` throws `ArgumentOutOfRangeException`. Since that type derives from `ArgumentException`, using it for the first case too would satisfy `Assert.Throws<ArgumentException>`; the test also compares `GetType()`, so each case needs its own type.
5. For `CountAdults`, run the tests first: the report names `IndexOutOfRangeException`. Pressing **Run** prints the full exception, and its first `at` line is `Ages.CountAdults`. In that method the only array access is `ages[i]`, so the loop lets `i` reach an invalid index. With `i <= ages.Length` the last pass reads index `Length`; changing `<=` to `<` fixes it and leaves the rest of the method as it was.
