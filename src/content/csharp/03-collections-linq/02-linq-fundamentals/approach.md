1. `LargePaidOrderIds`: filter with one `Where` that checks both the status and `Total >= minimum` (the boundary is included). Sort with `OrderByDescending` on the total, then `ThenBy` on the id with `StringComparer.Ordinal`, so ties come out the same on every machine. `Select` the id and finish with `ToList()`.
2. Why `ThenBy`: a second `OrderBy` becomes the new primary key, so the list would be sorted by id and no longer by total. The test with two orders of 120 checks the tie-break.
3. `RevenueByCustomer`: drop the cancelled orders before grouping, so a customer with only cancelled orders never forms a group. `GroupBy` the customer, then `ToDictionary` with the key and the group's `Sum` of totals.
4. `CountByStatus`: `CountBy(order => order.Status)` returns key and count pairs; `ToDictionary` stores them. `GroupBy` plus `Count()` gives the same result in more steps. Statuses without orders never appear, because nothing produces their key.
5. `LargestTotal`: `Max` over an empty sequence of `decimal` throws. Project to the totals, call `DefaultIfEmpty()` so an empty input becomes a single `0`, and take the `Max`. `Max(order => (decimal?)order.Total) ?? 0m` is an equivalent nullable projection.
