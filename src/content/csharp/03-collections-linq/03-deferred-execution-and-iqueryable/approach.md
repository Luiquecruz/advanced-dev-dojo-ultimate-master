1. Sort the four methods by when their work should happen. `InStock` and `FirstExpensive` gain from deferred, streaming execution: they read only what the caller needs. `Summarize` and `ParseQuantities` must finish their reading inside the call.
2. `InStock` returns `products.Where(...)` itself. A trailing `ToList()` would read all five products at the call, and the test that counts reads before and after `First()` fails.
3. `FirstExpensive` uses `FirstOrDefault` with the price condition. It is a streaming element operator: it stops at the first product that matches, and it returns `null` (the default of `Product?`) when none does.
4. `Summarize` needs three results from one source. Each of `Count()`, `Sum(...)` and the second `Sum(...)` would start a new enumeration of the parameter: on a file or an API that is three reads. Materialize once with `ToList()`, then compute from the list; enumerating a `List<T>` does not touch the source again. A single `foreach` that adds up all three numbers works too.
5. `ParseQuantities` with only `Select` returns a recipe: `int.Parse` runs when the caller loops, so the `FormatException` appears far from the call. Ending the query with `ToList()` runs the parsing at the call, which is what the test asserts.
