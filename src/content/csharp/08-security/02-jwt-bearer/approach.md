1. Start with the first test. `Convert.FromBase64String("YQ")` throws, because standard Base64 needs `YQ==`, and `PDw_Pz4-` uses the URL alphabet. A JWT always uses the URL form, so every later step depends on decoding it correctly.
2. Treat the token as data you do not trust yet. Split on `.`, check the count, decode only the payload, and read each claim with `TryGetProperty`: a claim that may be absent is not an error, a required one that is absent is a malformed token. So is a payload that is not an object, or a time `DateTimeOffset` cannot hold: turn both into `FormatException`, or `Check` would crash instead of answering `Malformed`.
3. Handle the two legal shapes of `aud`. RFC 7519 allows one string or an array, so normalising both into one list keeps the audience check a simple `Contains`.
4. Order the checks the way the task lists them, so a token that breaks several rules reports the first one. An unreadable token stops at `Malformed` before any claim is compared.
5. Take the time from the injected `TimeProvider`. The tests pin the clock to 2025 and 2026; code that reads the system clock would judge every token by today's date. The skew widens both edges: `exp` is accepted up to five minutes late and `nbf` up to five minutes early.
6. Notice what is missing: nothing here proves who wrote the token. In an API, `AddJwtBearer` verifies the signature with the issuer's public key first, and only then are these claim checks worth anything.
