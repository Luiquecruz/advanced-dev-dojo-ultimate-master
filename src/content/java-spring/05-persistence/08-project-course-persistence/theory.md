# Project: Course Catalog Persistence

This closing project builds the persistence layer of a course catalog on PostgreSQL: entities with a has-many relationship, Flyway migrations, pagination, soft delete and an integration test against a real database in a container. You build it locally with JDK 25, Maven and Docker as a Spring Boot 4 application.

You need: JPA and Hibernate Basics, Spring Data Repositories, Relationships, Transactions, The N+1 Problem and Fetching, Paging and Sorting with Spring Data, Database Migrations and Soft Delete (modules 03 and 04 cover the Maven, test and Spring Boot basics this project uses).

## Goal

Create a Maven project `course-catalog` with the base package `com.example.catalog`. A `Course` has many `Lesson`s and many `Tag`s. The schema is created only by migrations, courses and lessons are soft-deleted, a list endpoint is paginated, and the tests run on PostgreSQL started by Testcontainers. Install JDK 25, Maven 3.9 or later and Docker Engine 28 or newer first, and check them with `java -version`, `mvn -v` and `docker info`.

## Features

- Dependencies: `spring-boot-starter-webmvc`, `spring-boot-starter-data-jpa`, `spring-boot-starter-flyway`, `flyway-database-postgresql` and `postgresql` (runtime); for tests `spring-boot-starter-data-jpa-test`, `spring-boot-starter-webmvc-test`, `spring-boot-testcontainers`, `testcontainers-junit-jupiter` and `testcontainers-postgresql`.
- A `docker-compose.yml` that runs PostgreSQL for local development.
- Migrations `V1` (`course`, `lesson`), `V2` (`tag`, `course_tag`) and `V3` (a partial unique index on the lower-cased active title), with `ddl-auto=validate` and `open-in-view=false`.
- Entities `Course`, `Lesson` and `Tag` with an owning `@ManyToOne` on `Lesson`, cascade and orphan removal from `Course`, a `Set<Tag>` many-to-many, and `@SQLDelete` plus `@SQLRestriction` on `Course` and `Lesson`.
- `CourseRepository` with paged `CourseSummary` projections and an entity graph for lessons.
- `CourseService` with transactional `create`, `list`, `lessonTitles`, `removeLesson` and `delete`, and a sort whitelist.
- `GET /api/courses` returning a `PageResponse` record.

## Acceptance criteria

The persistence tests use these fixed courses and roll back through `@DataJpaTest`. The HTTP criterion needs a separate full-context MockMvc test with the web MVC test starter. Use a Spring-managed container bean shared with the context, as in Integration Tests with Testcontainers, so cached contexts never retain a stopped container.

1. The application context starts with `validate` against PostgreSQL after Flyway applied `V1` to `V3`.
2. Creating `Java Basics` (BEGINNER) with lessons `Syntax` and `Types` and reading it back gives the titles in that order.
3. Removing the lesson at position 1 leaves `Types` as the only title, and `select count(*) from lesson where deleted_at is not null` returns 1.
4. Deleting `Spring Data` (INTERMEDIATE, lessons `Repositories`, `Queries`, `Paging`, tag `jpa`) makes `findById` return empty while its row and its 3 lesson rows have a `deleted_at` value.
5. With 25 BEGINNER courses titled `Course 01` to `Course 25`, page index 2 of size 10 sorted by title has 5 items, 25 elements, 3 pages and starts with `Course 21`.
6. With `Java Basics` (BEGINNER) and `Hibernate Internals` (ADVANCED), filtering by ADVANCED returns only `Hibernate Internals`.
7. After deleting `Java Basics`, creating `Java Basics` again works, but creating `java basics` while it is active throws `DataIntegrityViolationException` at flush.
8. Sorting by `password` throws `IllegalArgumentException`.
9. With an empty database, `GET /api/courses?page=0&size=10` returns `{"content":[],"page":0,"size":10,"totalElements":0,"totalPages":0}`.

## Suggested steps

1. Create the project, add the dependencies and the compose file, and start the database:

```yaml
services:
  postgres:
    image: postgres:17-alpine
    environment:
      POSTGRES_DB: catalog
      POSTGRES_USER: catalog
      POSTGRES_PASSWORD: catalog-local-only
    ports:
      - "127.0.0.1:5432:5432"
```

The loopback port binding assumes Docker Engine 28 or newer, the baseline for this project. Use that baseline before running the local setup on a shared network; the Docker port-publishing documentation explains the older-engine limitation.

2. Configure the application (fake local credentials, never reuse them anywhere real):

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/catalog
spring.datasource.username=catalog
spring.datasource.password=catalog-local-only
spring.jpa.hibernate.ddl-auto=validate
spring.jpa.open-in-view=false
```

3. Write the three migrations under `src/main/resources/db/migration`, using `GENERATED BY DEFAULT AS IDENTITY` keys and a `deleted_at` column on `course` and `lesson`.
4. Write the entities, with a protected constructor, `EnumType.STRING` for the level and helper methods that keep both sides of the lesson association in sync.
5. Write the repository, the service and the controller with a `@PageableDefault(size = 10, sort = {"title", "id"})` parameter.
6. Write the test class. Import the Spring-managed `PostgresTestConfiguration` bean from Integration Tests with Testcontainers, using the PostgreSQL container image and service connection:

```java
@DataJpaTest
@AutoConfigureTestDatabase(replace = AutoConfigureTestDatabase.Replace.NONE)
@Import({CourseService.class, PostgresTestConfiguration.class})
class CourseServiceIntegrationTests {

    // Inject the service and repositories needed by the criteria.
}
```

7. Call `repository.flush()` before asserting on SQL-level effects such as constraints and `deleted_at`, because the test transaction rolls back and never commits.
8. Run `mvn test`, then `docker compose up -d`, `mvn spring-boot:run` and `curl "http://localhost:8080/api/courses?page=0&size=10"`. Stop with `docker compose down -v`.

## Stretch goals

- Add `@Version` to `Course` with a `V4` migration for its version column. Change its custom delete to bind `WHERE id = ? AND version = ?` (id first), increment the version, and configure `verify = Expectation.RowCount.class`. Test a stale update, a successful soft delete and a stale deletion; versioned custom SQL needs the extra bind parameter.
- Add keyset pagination with a `Window` for a feed of the newest courses.
- Add a scheduled job that purges rows deleted more than 90 days ago with a native query.

## Common mistakes

- Starting the tests without Docker running. Testcontainers needs a reachable Docker daemon, and the failure message points at Docker, not at your code.
- Leaving `ddl-auto` on `update` or `create-drop`, so a wrong mapping is hidden instead of failing at startup.
- Forgetting `@SQLDelete` on `Lesson`, so removing a course hard-deletes its lessons.
- Sorting a page by title only, so rows with equal titles move between pages.

## In practice

This is the shape of a real persistence layer: schema owned by migrations, entities that protect their own invariants, queries shaped per use case, transactions on the service and tests that use the production database engine. Keep the compose file and the migrations in the repository so a new teammate runs one command to get a working database.
