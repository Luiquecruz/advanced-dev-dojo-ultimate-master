Neither limiter needs a timer: on every call, first bring the state up to date from the time that passed since the last call, then decide. For the token bucket that means turning elapsed milliseconds into tokens; for the sliding window counter it means noticing that the window changed.
---
For the token bucket, `Refill()` reads `_now()` once into `time`, adds `(time - _last) * _refillPerSecond / 1000` tokens, caps with `Math.Min(_capacity, ...)` and stores `_last = time`. For the sliding window counter, add a `_previous` count next to `_current`: when the window start changes, a move of exactly `_windowMs` makes the old current count the previous one, and a bigger move means `_previous = 0`.
---
After rolling the windows, weight the previous count by the part of it that still overlaps: `(double)_previous * (_windowMs - (time - start)) / _windowMs + _current`. The `(double)` keeps the fraction of the weighted count, which `/` between two whole numbers would drop. Reject when that estimate is `>= _limit`, and add one to `_current` only for accepted requests.
