1. Think of the ring as a sorted array of positions. "Clockwise from the key" means "the first position at or after the key's hash", and "the ring wraps" means "if there is none, take the first element". That turns the ring into a lower-bound binary search plus one special case.
2. Store virtual nodes, not physical nodes, on the ring, each remembering its physical owner. Every placement question (who owns a key, which keys move) is answered by positions; the physical name is only read at the end.
3. Adding a node only inserts positions, so a key can only change owner if a new position now sits between the key and its old owner: it can only move to the new node. Removing a node only deletes positions, so only its own keys move, to whatever comes next clockwise. Check that your code never recomputes anything that depends on the number of nodes.
4. For replicas, keep walking clockwise from the owner's position and skip owners already collected, because several consecutive positions may belong to the same machine. Cap the result at the number of physical nodes so the walk always ends.
