1. Separate the two questions a semantic cache answers: *may* this entry serve this request, and *is* it close enough. The first is an exact comparison of scopes, the second a similarity against a threshold. Similarity can never answer the first question, so the scope filter runs before any cosine is computed.
2. Encode the scope without ambiguity. Joining the fields with a separator lets tenant `a|b` with model `c` produce the same key as tenant `a` with model `b|c`; a JSON array keeps the boundaries between fields, and a hash of it would keep keys short in production.
3. Pay for embeddings once: the vector of a stored prompt is computed in `Store`, so a lookup costs one embedding call however many entries exist, which matters when `embed` is a paid network call.
4. Search for the best match, not the first acceptable one, and apply the threshold to that best similarity. The threshold decides whether an answer is reused; the ranking decides which one.
5. In the gateway, check the cache before awaiting any provider, and store only successful answers: a cached failure would be served until the entry expires.
6. Classify each exception before acting on it. `429`, `5xx` and timeouts describe the provider's state and justify trying the next one; any other exception describes the request and would fail everywhere, so it goes straight back to the caller. An exception filter expresses that split without catching what it does not handle. Keep the last exception, so a full outage reports what actually happened.
