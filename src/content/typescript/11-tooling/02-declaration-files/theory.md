## Types without implementation

A **declaration file** (`.d.ts`) describes the shape of JavaScript code without containing any runtime code. It is how TypeScript understands plain JavaScript libraries, the browser, Node and its own standard library (`lib.esnext.d.ts` is just a big declaration file).

```ts
// greeter.d.ts
export declare function greet(name: string): string;
export declare const version: string;
export interface GreetOptions {
  loud?: boolean;
}
```

The `declare` keyword says "this exists at runtime, trust me". Declaration files may only contain types and `declare`d values: no function bodies, no initialisers.

## Where declarations come from

1. **Bundled with the package**: modern libraries ship their own `.d.ts` files and point to them with the `types` field (or a `types` condition inside `exports`) in `package.json`.
2. **DefinitelyTyped**: community types published as `@types/<package>`, e.g. `npm install -D @types/node`.
3. **Generated by you**: `"declaration": true` makes `tsc` emit a `.d.ts` next to every `.js` file of your library.
4. **Hand-written**: for untyped dependencies or global values injected by a script tag.

### TypeScript 6.0: types defaults to []

Older versions automatically loaded **every** package under `node_modules/@types` as global types. That slowed builds and polluted the global scope (a test runner's `describe` showing up in app code). TypeScript 6.0 changed the default of `types` to `[]`, so you now opt in explicitly:

```json
{
  "compilerOptions": {
    "types": ["node", "vitest/globals"]
  }
}
```

Modules you **import** still find their `@types` package automatically; the list only controls ambient, global types. `"types": ["*"]` restores the old behavior.

## Ambient module declarations

To type a package that has no types, declare the module yourself:

```ts
// vendor.d.ts
declare module 'legacy-chart' {
  export function draw(data: number[]): void;
}
```

A shorthand `declare module 'legacy-chart';` types every import from it as `any`: a quick escape hatch, not a solution.

Wildcards type non-code imports handled by a bundler:

```ts
declare module '*.svg' {
  const url: string;
  export default url;
}
```

## Global declarations and augmentation

Values that exist globally (injected by a script tag or a framework) are declared with `declare global` from inside a module, or at the top level of a script `.d.ts`:

```ts
export {};

declare global {
  interface Window {
    analytics: { track(event: string): void };
  }
  const __APP_VERSION__: string;
}
```

**Module augmentation** adds members to a library's interfaces through declaration merging. Frameworks rely on it, for example to type router metadata or Vue's global properties:

```ts
import 'vue-router';

declare module 'vue-router' {
  interface RouteMeta {
    requiresAuth?: boolean;
  }
}
```

## Library authoring flags

- `declaration` emits `.d.ts` files; `declarationMap` lets editors "go to definition" into your `.ts` sources.
- `emitDeclarationOnly` emits only types, when a bundler produces the JavaScript.
- `isolatedDeclarations` (5.5+) requires explicit types on exports, so tools can generate `.d.ts` files per file, in parallel, without running the type checker.
- `skipLibCheck` skips type checking **inside** `.d.ts` files. It speeds up builds and avoids errors in third-party types; nearly every project enables it.

## Legacy notes

- Triple-slash directives (`/// <reference types="node" />`, `/// <reference path="..." />`) predate modules and the `types` option. Prefer imports and `tsconfig.json`.
- `declare namespace` for grouping global APIs is still common in old typings, but the `module Foo {}` keyword form for namespaces is deprecated in TypeScript 6.0 and removed in 7.0. `declare module 'name'` with a string is unaffected.
- Typings managers such as `typings` and `tsd` were replaced by `@types` in TypeScript 2.0.

## Pitfalls

- A `.d.ts` file is trusted blindly. If it says a function returns `string` but it returns `undefined`, the compiler cannot notice.
- A top-level `import` or `export` turns a `.d.ts` file into a module, so its declarations stop being global. Wrap them in `declare global`.
- Do not write `.d.ts` files for your own TypeScript code; let `declaration: true` generate them.
